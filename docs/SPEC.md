# TestPilot AI 需求规格初稿 V1

智能软件测试生成与缺陷检测平台面向需要验证 Python 代码质量的开发、测试与质量工程人员。三天交付目标是让测试人员从一份代码得到可复查的测试结果，让开发人员可以对修复前后的结果做回归比较。项目组长陈帅廷统一协调五个等额工作包。

## 需求来源与优先级

依据 TP-PHASE-01 任务书、PyCharm 原生 Run 的 P0 补充要求及 2026-11-27 的[正式需求访谈](../transcripts/requirements-interview.md)。三项答复均为“沿用任务书”。采用 Python 单服务方案。首次配置好解释器与依赖后，运行、调试、渲染页面和调用接口均从根目录 `main.py` 进入。

## 本阶段的验收场景

1. 在 Windows 11 用 PyCharm 打开项目根目录并配置项目解释器，打开 `main.py` 点击 Run。默认浏览器应自动显示 `http://127.0.0.1:8000` 的 Dashboard。
2. Dashboard 显示 FastAPI 与 SQLite 的实际连接状态。用户点击“运行自检”，页面显示固定可信样例的 Pytest 结果。失败时应能区分连接、数据库和执行器故障。
3. 已启动时再启动相同端口，第二个进程应给出可读诊断并退出，原服务仍能响应。停止原服务后，同一端口可再次使用。
4. 开发人员可在同一个 Python 入口下启动 Debug 并命中断点。开发与演示模式可区分，均无需管理员权限及前端开发服务器。
5. 项目保留已有文件，形成 Git 基线、五个工作包、五人贡献分配、证据日志和独立阶段报告。阶段结束时逐项区分实测、待办与待确认事项。

## 三天业务闭环

| 功能 | 用户操作 | 业务验收条件（后续阶段） |
| --- | --- | --- |
| F01 项目管理与文件导入 | 建立项目，选择 Python 源文件 | 可重新打开项目，识别文件版本，无效输入有定位信息 |
| F02 Python AST 分析 | 选择已导入版本进行分析 | 可追溯到原文件、符号及行号，语法错误可定位，解析阶段不执行源码 |
| F03 AI 测试用例生成 | 基于分析结果生成并审阅候选测试 | 测试关联目标函数和来源，可检查与保存；记录生成方式，覆盖示例与适用的属性测试 |
| F04 自动化执行 | 选择用例与被测版本启动受限运行 | 显示真实通过、失败、错误或超时，留存环境、结果和运行标识 |
| F05 Bug 与回归 | 从失败记录建缺陷，关联修复版本并重跑 | 修复前后的证据可追踪；回归成功后才可按流程确认修复 |
| F06 评估与报告 | 选择运行记录并导出结果 | 报告含样本、测试计数、覆盖率口径、缺陷和回归状态，可与原始结果核对 |

## 约束与待细化事项

核心业务从初始化验收后开发。本阶段只接受平台内置自检。业务运行器启用前，需独立验证导入代码与生成代码的执行隔离、网络和文件权限、资源限额及超时清理。子进程和虚拟环境本身不能提供这些隔离保证。

生成服务优先使用现有工具和模型；启动项目与运行本地自检无需模型密钥。具体模型、导入规模及依赖支持范围、导出格式、质量评分权重尚待业务阶段确定。第一轮集成可用自建的小型 Python 样例验证闭环，此选择是团队实施建议。详细依赖关系、验收指标及责任归属见 [FEATURE_MAP](FEATURE_MAP.md) 和 [三天计划](THREE_DAY_PLAN.md)。
