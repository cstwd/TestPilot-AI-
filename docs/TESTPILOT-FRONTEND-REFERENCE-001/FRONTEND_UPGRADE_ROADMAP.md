## 回归如何执行

下列命令供实施阶段在项目根目录通过 PowerShell 执行。项目内已有解释器、测试文件和选择器，本研究仅检查命令对应的源码。浏览器测试通过真实 `main.py`、回环地址及临时 SQLite 工作；Windows 默认使用本地 Edge。正式发版另从 PyCharm 点击 Run 和 Debug。为保留既有报告，复验时让 `TESTPILOT_CAPTURE_DASHBOARD` 和 `TESTPILOT_CAPTURE_REPORTS` 保持未设置，新截图和日志使用新验收目录。[环境与临时服务](../../tests/test_dashboard.py#L19) · [375px 检查](../../tests/ui_workbench.py#L13) · [历史报告写入开关](../../tests/test_phase02_flow.py#L26)

```powershell
$py = '.\.venv\Scripts\python.exe'
git rev-parse HEAD
git status --short --branch
& $py -m pytest tests --collect-only -q
& $py -m pytest tests/test_startup.py tests/test_dashboard.py -q
& $py -m pytest tests/test_f01.py tests/ui_workbench.py::test_f01 -q
& $py -m pytest tests/test_f02.py tests/ui_workbench.py::test_f02 -q
& $py -m pytest tests/test_f03.py tests/ui_workbench.py::test_f03 -q
& $py -m pytest tests/test_f04.py tests/test_runner.py tests/ui_workbench.py::test_f04 -q
& $py -m pytest tests/test_f05.py tests/ui_workbench.py::test_f05 -q
& $py -m pytest tests/test_f06.py tests/ui_workbench.py::test_f06 -q
& $py -m pytest tests/test_phase02_flow.py -q -s
& $py -m pytest tests -q
```

- **功能回归**。每迁一页，执行对应模块、浏览器用例及已迁移的相邻路径。自动闭环从真实缺陷版源码生成测试、取得失败节点、登记缺陷，用修复版和原套件回归，再核对两个版本的导出、SHA-256 与各自的 run ID。[端到端断言第 46 行起](../../tests/test_phase02_flow.py#L46)
- **交互验收**。在现有 375×812 和 1366×900 规格基础上，补验六页桌面视图、中等窗口、200% 缩放与仅键盘操作。逐项验证折叠后焦点可返回、长行只在代码窗内滚动、输出和错误可读、后退/刷新可重建上下文。记录真实失败路径与屏幕宽度，不以替换快照消除失败。[现有桌面与窄屏检查](../../tests/test_dashboard.py#L66) · [六页现有浏览器用例](../../tests/ui_workbench.py#L26)
- **状态与安全边界**。后端成功返回的运行结果可含失败或错误用例；页面分别提示请求状态和测试结果。对受限执行器未就绪、并发已占用、输出截断等保留原诊断；查看源文件、Diff 和日志时按文本渲染；首页固定自检走原入口。[可信自检路由](../../backend/app.py#L58) · [F04 隔离边界与历史实测](../../F04_MODULE_ACCEPTANCE.md#L5)
- **回退**。每一批独立提交并记下最近一次通过回归的前端提交；公共样式先限定在迁移页，避免一次发布改变所有旧页。发现串项目、错版本、结果对不上或 P0 入口失效即暂停下一批。在实施分支撤回引入问题的页面提交及相依样式，复验该页、邻接路径与 P0；用同一组 ID 从旧布局重新读取已保存的证据。无需恢复业务数据库。规范变更另行提交。[组件上下文与链接构造](../../frontend/static/workbench.js#L28) · [工程交付约定](../../AGENTS.md#L21)
