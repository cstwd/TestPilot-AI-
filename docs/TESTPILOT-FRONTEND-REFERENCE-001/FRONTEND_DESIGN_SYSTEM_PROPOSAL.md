## 色彩与层次

基础值集中在一个同源样式入口；页面调用语义变量，组件仅在确需变化处做局部映射。例如运行结果的“通过”、回归的“已解决”共享成功色，但保留各自标签。初期可让现有 `--blue`、`--line` 等别名继续解析，逐页切换。

| 建议语义变量 | 色值 | 用法 |
| --- | --- | --- |
| `--canvas` / `--surface` / `--surface-inset` | `#F3F6F8` / `#FFFFFF` / `#EDF3F6` | 页面底板、工作面、只读源码和日志底色 |
| `--text` / `--text-muted` | `#172F40` / `#506575` | 正文、来源与说明；文件名和指标值用正文色 |
| `--action` / `--selected-bg` | `#123F61` / `#EAF4F8` | 主操作白字深蓝底；选中行用浅蓝底、行首标记和当前项语义 |
| `--accent-on-dark` | `#93E3F1` | 深蓝面板上的强调；亮底页面沿用深蓝链接 |
| `--divider` / `--control-edge` / `--focus` | `#D6DFE5` / `#647D8C` / `#875500` | 1 px 面板分隔、输入框边界、键盘焦点；深蓝按钮周围保留 2 px 白色间隔 |
| `--ok-fg` / `--ok-bg` | `#176541` / `#ECF6EF` | 已证实通过、已解决；标签写明通过的是语法检查或某次运行 |
| `--warn-fg` / `--warn-bg` | `#785000` / `#FFF5D8` | 超时、执行器不可用；标签写明发生的事件和可采取的动作 |
| `--error-fg` / `--error-bg` | `#933C24` / `#FCF0EC` | 断言失败、错误；用不同文字和详情入口区分 |

按 sRGB 相对亮度计算，正文／白色为 13.84∶1，辅助文字／白色为 6.07∶1，白字／深蓝为 11.00∶1；成功、警告、失败三个前景／背景组合分别为 6.39、6.55、6.46∶1。以上为提案纯色色对的计算值。半透明叠层、浏览器强制色和禁用状态留到页面验收时检查。淡色分隔线仅分组，输入边界与焦点使用专门的高对比色。

## 字体、几何与图形

| 部位 | 建议规格 | 检查方法 |
| --- | --- | --- |
| 页标题、分区标题、正文、辅助信息 | 28/36、18/26、15/24、13/20 px（字号/行高）；标题 600，正文 400。沿用现有界面字体栈 | 在 Windows 中文环境读长文件名、缺陷标题及中英混排，200% 缩放后能阅读完整文本 |
| 源码、行号、日志、摘要 | Consolas、Microsoft YaHei、monospace；13/21 px；指标数字用等宽数字，SHA-256 可在详情折行 | 源码保存空白与缩进，阅读面独立横滚；切换事实记录后行号和摘要随之更新 |
| 间距与尺寸 | 4、8、12、16、24、32 px；行内图文间距 8，表单字段间距 12，桌面分区内边距 24，窄屏 16。桌面操作目标至少 36×36，触屏目标建议 44×44 px | 比较相邻页同一选择器、记录行与操作按钮的对齐边缘 |
| 轮廓与阴影 | 控件圆角 5 px，面板 10 px；正文面板使用 1 px 分隔。临时菜单或对话框可用一层中性阴影，如垂直偏移 6、模糊 20 px、透明度 14% | 灰度下仍能找到打开的面板、当前行和键盘焦点 |
| 图标与图表 | 建议使用项目自有的小套单色线性符号，16 或 20 px、1.5–2 px 描边，使用当前文字色。常用动词保留文字；只有图标的按钮提供可访问名称 | 折叠箭头配展开状态，搜索配标签，Diff 行配“＋／−”与行号；质量分布图旁有数值表 |

桌面宽屏按**工作内容区**分配列。举例，F02 资源区 220 px、源码至少 420 px、检查区 260 px，加上两条分隔及槽宽后才启用三栏。依次收合右侧检查区、左侧资源区；内容宽度仍不足时切换为符号、源码、详情三个顺序视图。720 px 及以下保持单列，导航和上下文位于正文前。拖动分隔线是可选增强，应同时提供按钮收合、键盘调宽和复位。具体六页阅读顺序见[页面映射](TESTPILOT_PAGE_LAYOUT_MAPPING.md)。

## 如何交付和验收

1. WP02 维护变量表、组件状态表和六页示例，WP01 核查链接参数和字段语义，WP05 保存每次人工评审与浏览器证据。新增变量须说明适用角色、对比色对和首个消费组件。
2. 首页与工作台先共享颜色和焦点样式，再逐页替换布局。共用 Jinja 宏负责结构和可访问名称，共用 CSS 负责间距及状态，原生模块按现有页面入口处理请求。复用现有页面 ID 与 `data-dest` 绑定关系；将相同业务状态映射到公共标签。
3. 在 Edge 的 1440、1024、720、375 px 视口及 200% 缩放复核。长 nodeid、长中文标题、空记录和多行日志均须可读；只有有意设计的代码面或表格容器出现独立横滚。Tab/Shift+Tab 可到达并离开全部控件，Esc 收起浮层并返回触发控件，折叠后焦点停在可见元素。
4. 用相同项目、版本、套件和运行 ID 对照新旧页面；检查空结果、失败、超时、不可用、覆盖率缺失和真实 0%。减少动态效果时立即切换面板。颜色之外的文字、行号和图例须能完整还原业务含义。

这些是后续实现阶段的验收用例。本阶段完成了样式、模板和渲染路径的源码核对，以及提案色对的数值计算；页面交互验收与人工签收留待实施。
