
# Demo Lab 演示操作手册

## 打开工作台

用项目 Python 3.13 解释器在 PyCharm 运行根目录 `main.py`。首页的「打开 Demo Lab」进入 `http://127.0.0.1:8000/workbench/demo-lab`。服务按既有 `TESTPILOT_DATA_DIR` 配置定位数据目录，Demo Lab 使用其中的 `testpilot.demo-lab.sqlite3`。如需演讲专用空历史，可在独立 PyCharm Run 配置指定新的 `TESTPILOT_DATA_DIR`。

## 展示一次完整回归

1. 从样本库选择 `unit_scaling.py`，用类型和领域筛选验证搜索范围。右侧「源码」可并排看原版与修复版。「公开合同」展示这一演示生成出的可执行测试。
2. 保持「公开合同 / 本地模板」，勾选「通过后运行 F13」，点击「运行演示」。每次点击都创建独立项目、执行 ID 与报告。
3. 查看执行步骤及 Pytest 原始日志。原版在 `metric_kilometers(1250)` 返回 `1`，公开合同断言为 `1.25`。报告分别展示断言位置与可定位到的原版函数位置。
4. 系统导入同名修复版 v2，以 v1 的同一套件复跑。核对两次运行的套件 ID，以及原失败节点在修复版通过并关闭缺陷。
5. 查看 F13 原版基线、算子分类和结果。要展示存活位置，另运行 `geometry_calculator.py` 并展开「定位存活变异」。全量得分使用整个变异清单，有效得分的分母仅扣除执行错误。超时、取消、未运行及等价候选单独显示。
6. 点击「下载完整 JSON」并保存文件。报告可通过「运行历史」或顶部「报告中心」重新打开。F06 和 F13 原始快照也可打开，报告内的数字可与独立记录复核。

## 选样

| 场景 | 样本 |
| --- | --- |
| GOOD 原版通过 | `calculator` |
| BUGGY 原版缺陷复现 | `unit_scaling`、`binary_search`、`volume_discount` |
| CHALLENGE 含组合逻辑 | `booking_timezones`、`member_checkout`、`filtered_pagination` |

公开课堂合同由本阶段单独编写。其他样本使用产品的一般模板，可从测试结果和修复版对照判断适用性。

## 本机 AI

在健康检查通过的本机模型环境，选择「本机 AI」。服务先通过 [固定模型部署](../phase06/DEPLOYMENT.md) 中的源码理解能力取得结构化结果，再运行正式 AI 生成。报告记录模型来源、运行 ID 和分析输出。资源或协议失败时，执行流程保留诊断。要继续演示可以手动选择模板并新建一次运行。

## 中断和状态

离开页面后，已提交的运行由本机服务继续执行。刷新后可读取当前状态。Windows 进程停止中断的运行保留已提交证据，重启后标记中断。已有一个演示运行时，服务拒绝并发新演示。用「重新执行」产生新的记录，历史报告可继续读取。

同源只读入口为 `GET /api/demo-lab/runs/{id}`，导出为 `GET /api/demo-lab/runs/{id}/export`。返回相同的完整报告数据。原始 Pytest 输出、分析来源、执行用例、缺陷、修复、回归和变异记录均随该运行 ID 保存。
