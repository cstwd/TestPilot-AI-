# 三天交付计划

以下按项目工作日安排。首次初始化验收通过后再进入核心业务开发。

| 时间 | 工作与责任 | 交接物 | 验收关口 |
| --- | --- | --- | --- |
| 第一天 · 初始化 | WP01 搭建单服务；WP02 明确需求与 Dashboard；WP03 提供可信自检；WP04 制定质量与安全边界；WP05 建立工作包和证据目录 | SPEC、入口、环境说明、工作包、启动实测 | 以 TP-PHASE-01 单独报告核对 P0 入口和证据。未验证项需记录影响 |
| 第二天 · 最短业务路径 | WP01 做 F01、F02；WP02 接入项目和符号页面；WP03 完成 F03 并准备成功、失败样例；WP04 验收隔离后与 WP03 接入 F04；WP05 维护联调和审查记录 | 项目、分析结果、审阅后的测试、真实运行证据 | 阶段报告演示导入 → 分析 → 生成 → 受限执行。隔离未过则暂停 F04 业务运行 |
| 第三天 · 回归与交付 | WP04 串联 F05；WP03 核对覆盖率和离线评测；WP02 展示缺陷和报告；WP05 导出 F06、组织复核归档；WP01 负责集成 | 失败与修复后运行记录、缺陷状态、质量报告、演示材料 | 独立阶段报告核对六项功能、证据、环境、已知限制；复查 PyCharm Run 和 Debug 路径 |

项目组长陈帅廷统一协调依赖和范围调整。遇到时间压力，先保留可复查的单项目闭环；批量导入、复杂报告样式及额外模型接入可记录为后续事项。变更影响和实际决策进入协作日志。
