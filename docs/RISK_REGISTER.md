| R03 · 不受信任的项目源码或生成测试在开发机执行 | 马雪朋 · WP04 | 业务入口接收源码并直接交给本机 Python/Pytest | 在受限执行器及隔离绕过防护验收前关闭业务运行；检查网络、文件访问、资源限额、超时清理和残留进程 |
| R04 · 生成结果波动或模型不可用 | 赵君豪 · WP03 | 固定样例无法收集测试、生成中断、评测结果漂移 | 保存输入摘要、生成渠道和结果版本；固定评测集重跑；明确标记失败或跳过 |
| R05 · 多次运行之间证据混淆 | 马雪朋 · WP04 | 缺陷仅有当前状态，回归覆盖原失败记录 | 使用运行标识关联缺陷、用例版本和修复前后结果，通过抽样追溯复核 |
| R06 · 三天内缺少联调时间 | 陈帅廷 · WP01 | 第二天结束时仍无法从真实样例走到运行结果 | 统一接口，优先单项目路径；组长记录延期范围和实际影响 |
| R07 · 责任分配被误记为实际工时或提交 | 王选中 · WP05 | 日志将代理操作署在人类名下，或引用不存在的提交 | 工作记录区分责任人与实际操作人；用 Git 历史、测试输出和阶段报告逐项复核 |

每个阶段由对应责任包复查触发信号，已出现的问题记入 `collab-log/bugs/`，并关联受影响功能与复验结果。
