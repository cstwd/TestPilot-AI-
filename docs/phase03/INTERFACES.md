# PHASE-03 模块接口与数据契约

工作流沿用 F01 的不可变文件 ID，单独建立任务和阶段事件。每个事件有 UUID、UTC 时间戳、类型、状态、任务 ID、前序事件 ID 以及 JSON 数据。任务绑定项目文件与目标。API 通过任务 ID 回读完整记录。所有新表与旧接口共存，兼容既有 SQLite 版本 1。

| 类型 | 产生模块 | 主要内容 |
| --- | --- | --- |
| SourceAnalysis | F07 | 文件身份与源码摘要，符号、参数、控制流、依赖、诊断 |
| TestStrategy | F08 | 目标、测试类型、目的、输入、预期、依据 |
| GeneratedTest | F09 | 源码、来源模式、模型与请求元数据、校验、摘要、降级原因 |
| TestExecution | F10 | 固定 Pytest 真实执行的状态、个案、退出码、两路输出与耗时 |
| CoverageResult | F10 | 实测行、分支分子及分母，无法测得时用 null |
| FailureAnalysis | F11 | 节点、异常、断言、源码位置、可能归属及依据 |
| RepairAttempt | F12 | 触发依据、尝试号、前后测试摘要、重复拦截和停止原因 |
| TestReport | 集成 | 初次及最终执行、结论、来源、任务状态及完整事件索引 |

F07 接受源码或原始字节并返回静态分析字典；F08 接受分析及目标；F09 复用 F03 校验和模板接口并增加策略与反馈上下文；F10 以选项扩展既有执行器；F11 使用运行证据及明确契约判读；F12 在有限次数内只更新生成测试。任务内新事件按顺序持久化，初次记录保留。网页从同一服务选择已导入的文件版本并发起或查看任务。
