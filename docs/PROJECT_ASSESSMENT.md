# 项目评估 · TP-PHASE-01

**阶段目标**　在三天开发周期的第一阶段交付 Windows 11 下可从 PyCharm 运行的单服务骨架，建立后续功能的责任边界和验收依据。

| 评估项 | 当前判断 | 验收依据或后续决定 |
| --- | --- | --- |
| 工作区 | 初始目录含 PyCharm 示例入口和 IDE 配置 | 核对原入口备份，排除本机 IDE 私有设置，Git 记录应显示真实变更 |
| 启动体验 | Python 项目解释器安装依赖后，根入口统一服务页面和 API | 审查实际启动、浏览器、端口冲突与重启证据；IDE 界面操作须标明验证方式 |
| 技术复杂度 | Jinja2 静态页面与 FastAPI 同源，三天内可减少独立前端部署工作 | Dashboard 需能从页面调用真实的后端自检，接口失败应有反馈 |
| AI 能力 | 项目可先使用现有 Codex 或可用模型，费用与服务可用性是约束 | WP03 记录实际生成渠道和输入版本，离线评测使用固定样例 |
| 执行隔离 | 用户代码执行是后续闭环的关键依赖 | WP04 先验收受限环境；仅有超时或普通子进程不足以开放业务运行 |
| 团队协作 | 五人责任与贡献目标已经分配 | 工作包用阶段证据验收；操作署名按实际执行记录 |

**交付判断**　初始化范围的判定由 [阶段验收报告](../TP_PHASE_01_ACCEPTANCE.md) 汇总。F01–F06 的完成度须在对应业务阶段另行核验。三天安排优先验证“一份小项目、一次失败、一次修复回归、一份报告”的完整路径。
