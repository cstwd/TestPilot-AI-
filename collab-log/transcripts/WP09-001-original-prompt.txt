# WP09-001

# TESTPILOT AI 全站统一整合与最终验收

## 一、任务目标

对 TestPilot AI 六大业务页面进行统一整合、视觉一致性审查、端到端业务验收和性能回归。



六个页面均已完成独立升级：

- F01 Project Explorer
- F02 Visual Intelligence Studio
- F03 AI Test Generation Studio
- F04 Test Execution Control Center
- F05 Bug Intelligence Center
- F06 Quality Intelligence Center

本阶段不重新设计页面，不随意增加功能。



目标是将六个独立工作台整合成一个完整、统一、稳定、可演示的 AI 软件测试产品。

## 二、前置基线审计

开始前必须：

1. 检查当前 Git HEAD。
2. 检查全部工作区修改。
3. 核对 F01–F06 各自最终提交。
4. 检查 Design System V1。
5. 检查公共组件复用情况。
6. 检查六个页面的路由。
7. 检查 API 契约。
8. 检查数据库和数据快照。
9. 收集六页现有自动化测试。
10. 建立全站验收基线。

禁止覆盖其他未提交工作。

## 三、全站视觉一致性审查

检查：

- 全局背景和面板颜色。
- 顶部导航和侧边栏。
- 字体和字号。
- 图标。
- 按钮。
- 搜索框。
- 表格。
- Badge。
- Drawer。
- Modal。
- Inspector。
- Loading、Empty、Error 状态。
- 代码阅读器。
- 终端和 Diff。
- 图表。

以 F02 的 GitNexus-inspired Dark Workspace 为主要视觉标杆。



保留 F02 动态知识图谱的 Cinematic 效果。



只修复真实的不一致，不为追求像素统一而破坏各页面业务布局。

## 四、完整业务闭环验收

使用同一个独立测试项目贯穿六页：



F01：

- 创建项目。
- 导入 Python 文件。
- 创建文件 v1。
- 修改文件并导入 v2。

F02：

- 分别分析 v1 和 v2。
- 检查真实 AST 图谱。
- 选择目标函数。
- 核对源码位置。

F03：

- 选择目标函数。
- 生成测试套件。
- 静态检查。
- 检查真实首次运行结果。

F04：

- 执行原始测试套件。
- 检查运行 ID。
- 检查用例结果和日志。

F05：

- 登记真实失败。
- 选择修复版本。
- 查看 Diff。
- 执行原套件回归。
- 验证缺陷状态。
- 保留所有历史运行。

F06：

- 选择对应运行。
- 检查测试计数。
- 检查覆盖率。
- 查看缺陷和回归信息。
- 导出 HTML 和 JSON。
- 验证报告快照一致。

完整记录：\
project_id、file_id、version_id、symbol、suite_id、run_id、bug_id、report_snapshot。



所有数据必须来自真实业务记录。

## 五、跨页面交互检查

重点验证：

- 页面切换后上下文保留。
- 项目切换后旧项目数据清除。
- 浏览器刷新恢复正确记录。
- 浏览器后退恢复原选择。
- 深链接直接打开正确页面。
- F04 失败用例正确进入 F05。
- F05 回归记录能够返回 F04。
- F06 能够进入对应运行和缺陷详情。

## 六、响应式验收

统一检查：



1920×1080\
1440×900\
1280×800\
1024×768\
768×1024\
390×844



六页全部检查。



特别关注：

- 图谱。
- 代码查看器。
- Diff。
- 测试日志。
- 质量图表。
- 项目版本列表。

不得出现页面溢出、内容宽度归零、无法操作或信息丢失。

## 七、稳定性和性能回归

- 六页完整浏览器回归。
- 原有自动化测试回归。
- 检查控制台异常。
- 检查重复请求。
- 检查动画离页停止。
- 检查事件监听器清理。
- 检查长日志性能。
- 检查报告快照稳定性。
- 检查大型图谱渲染。
- 检查多次刷新和切换。

保留已有通过的测试基线，不得通过修改测试断言来消除失败。

## 八、视觉质量提升

在不破坏现有业务的前提下，重点检查：

1. 六页是否具有一致的产品辨识度。
2. 是否存在过多空白区域。
3. 是否存在信息拥挤区域。
4. 主要操作是否容易找到。
5. 页面标题、指标、辅助说明层级是否合理。
6. 图谱、代码、日志是否具有良好的阅读体验。
7. 动效是否自然、流畅、不过度。
8. 手机端是否保持清晰的操作顺序。

不要为了炫酷牺牲可读性。

- 六页统一 Design System。
- 六页导航和上下文一致。
- 六页功能正常。
- 完整业务闭环通过。
- 历史数据可追溯。
- 页面与导出数据一致。
- 六种分辨率通过。
- 原有测试保持通过。
- 新增测试全部通过。
- 没有未处理的 P0/P1 缺陷。

完成后停止，等待人工最终签收。
