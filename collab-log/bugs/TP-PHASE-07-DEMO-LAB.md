
# TP-PHASE-07 Demo Lab 问题与修复

归属 WP01、WP02、WP04。操作者 Codex。独立复核按仓库的 `testpilot-reviewer` 定义执行，成员签收待登记。

| 发现 | 最小修复 | 验证 |
| --- | --- | --- |
| 第二个服务实例启动时，可能把首个实例仍在执行的演示标为中断 | 为 Lab DB 增加 OS 锁，交由后台任务持有。恢复只在取得锁后执行，检查写入行仍属于进行中的运行 | 同数据库启动两个真实主服务，持锁时第二实例返回 409。释放锁并重启后记录为 interrupted |
| 原版结构化回溯丢失会影响缺陷定位，回归需要核对同一节点集合 | Lab 为原版和修复版使用 detailed WASI，缺陷关闭同时核对原版与修复版的节点、跳过状态和真实通过 | 六个样本均用同套件得到原节点失败转通过 |
| 若 Lab 复用主库，演示项目会进入正式项目列表 | 分离演示 SQLite，报告链接使用 Lab 运行 ID。侧库损坏时 Lab 端点返回 503，主工作台继续服务 | 主库项目列表保持空，模拟失效侧库时核心健康与项目接口通过 |
| 快速点击多份历史，早请求可能覆盖晚选择的报告 | 为样本选择与历史请求分别校验最新序号 | Edge 中实际运行后打开历史、刷新重读和报告中心 |
| 目录数 225 与校验输出 224 的统计对象不同 | 在工作包验收中统一按 225 个归档文件、其中 224 项清单记录陈述 | 冻结清单逐项复算 |
| 历史 F13 只报告全量分母 | 保留历史结果，另计算排除执行错误的分母，并在产品报告并列展示 | 历史 34/48 和 34/45 双口径，并以本期实际变异验证 |
