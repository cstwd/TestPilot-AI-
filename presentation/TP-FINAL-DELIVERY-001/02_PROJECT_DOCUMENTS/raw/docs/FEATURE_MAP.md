# 功能与验收映射

PHASE-01 验收本机单服务、Dashboard、数据库探测和可信自检。后续阶段通过同源工作台接通下列业务路径。各阶段记录继续保留，课程复验应标明具体提交和生成模式。

| 编号 | 功能与负责包 | 输入 → 输出 | 最小验收场景 | 已有验证与边界 |
| --- | --- | --- | --- | --- |
| F01 | 项目管理和文件导入 · WP01、WP02 | 项目名、Python 源文件 → 项目记录、文件清单 | 创建两个项目并导入不同文件，刷新后各自清单可恢复；不支持的文件和越界路径被拒绝，已有文件不受影响 | [版本、拒绝和恢复](../F01_MODULE_ACCEPTANCE.md)，单文件 UTF-8、128 KiB。 |
| F02 | Python AST 代码分析 · WP01 | 已导入文件 → 带文件与行号的分析结果 | 对含函数、类及语法错误的样例分别验证符号、定位和错误提示；分析阶段不执行源码 | [静态解析](../F02_MODULE_ACCEPTANCE.md)，智能理解按模型可用性独立验证。 |
| F03 | AI 测试用例生成 · WP03 | 符号、源码上下文、生成配置 → 可审阅的测试源码与生成记录 | 选定函数后生成普通用例和适用的属性测试，保留生成输入摘要，检查测试可收集；生成失败应可见 | [工作台模板](../reports/WP05-F03-001/F03_BROWSER_ACCEPTANCE.md)，[模型 API](../reports/phase06/E2E.md)。来宾原生 Hypothesis 当前会跳过。 |
| F04 | 自动化测试执行 · WP03、WP04 | 经选择的测试和目标代码 → 运行结果、耗时和日志 | 在通过隔离验收的环境运行预设成功、断言失败和超时样例，核对三个状态及清理结果 | [WASI/Pytest 实际执行](../F04_MODULE_ACCEPTANCE.md)。平台可信自检是独立的固定样例。 |
| F05 | Bug 管理和回归验证 · WP04 | 失败运行、修复版本 → 缺陷记录、回归证据 | 从失败断言创建缺陷，定位原运行；对修复版本用同一测试复跑，保留两次记录并按结果更新状态 | [真实原节点回归](../reports/WP09-001/END_TO_END_ACCEPTANCE.md)，已解决状态关联同一套件和原节点。 |
| F06 | 测试质量评估和报告导出 · WP03、WP04、WP05 | 运行记录、覆盖率、缺陷与回归 → 可导出报告 | 对固定样例核对用例数、通过/失败/错误数、覆盖率和缺陷链接；指标无数据时注明缺失，导出内容与页面一致 | [真实运行快照与导出](../reports/WP09-001/END_TO_END_ACCEPTANCE.md)，无采集值保留缺失。 |
| F07–F12 | 智能分析、生成、执行、归因与修正 · WP01、WP03、WP04 | 不可变文件和目标 → 按任务 ID 保存的证据 | 核对指定生成模式、初始执行、来源、带契约的有限修正与原始结果保留 | [七样例和归因实测](../reports/phase03/E2E.md)，不确定归因保留待复核。 |
| F13 | 固定清单变异测试 · WP04 | 完成的引擎任务和运行选项 → 会话、判定和报告 | 先验证原版，按清单逐项实跑并核对分母；补测保留原版和实际模型模式 | [模型与模板对照](../reports/phase06/MUTATIONS.md)，[新增 Demo Lab 模板回执](../demo/TestPilot-Demo-Lab/reports/MUTATION_EVALUATION.md)。 |
