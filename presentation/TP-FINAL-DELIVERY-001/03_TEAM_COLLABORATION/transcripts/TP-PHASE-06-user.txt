# TP-PHASE-06：Qwen3.8-27B 全系统统一模型迁移

## 一、项目决策

正式确定 Qwen3.8-27B UD-IQ3_XXS 为 TestPilot AI 全系统唯一 AI 推理模型。



模型运行环境：

- Windows 11
- RTX 5080 Laptop
- Ollama 本地模型服务
- Vulkan 后端
- 本地 GGUF 权重
- API 费用：0

禁止正式业务链路回退至 0.5B、3.8B 或其他小模型。

## 二、执行目标

1. 全面审计 F01、F02、F03、F04、F13 及其他 AI 调用入口。
2. 将所有正式 AI 推理入口统一迁移到 Qwen3.8-27B。
3. 建立统一模型服务层，禁止各模块自行指定模型。
4. 保留原有功能、接口和数据结构。
5. 保证模型输出遵守冻结的 JSON Schema 和模块协议。
6. 修复 TP-PHASE-05 已发现的源码理解输出格式问题。
7. 优化 Mutation Testing 反馈补测机制。
8. 完成全系统真实端到端回归。

## 三、模型服务架构

建立统一 Model Provider：

- 统一模型标识。
- 统一推理入口。
- 统一超时控制。
- 统一异常处理。
- 统一 JSON 解析与 Schema 校验。
- 统一日志与运行 ID。
- 统一 token 使用记录。
- 统一模型健康检查。

所有正式 AI 调用必须经过统一 Provider。



严禁模块绕过 Provider 直接调用其他模型。



模型启动时必须核验：

- 实际模型名称和版本。
- Ollama 服务状态。
- Vulkan 后端可用性。
- 权重身份与发布修订。
- 实际推理成功状态。

不能仅根据配置文件中的模型名称判断模型已加载。

## 四、性能与资源优化

不设置第二个 AI 模型作为备用推理模型。



可以优化：

- 上下文长度。
- Prompt 长度。
- 输出 Token 上限。
- 推理并发。
- 请求队列。
- KV Cache。
- 模型常驻。
- 重复上下文缓存。
- 批量任务调度。

以实际测试结果决定参数，不得凭空设置最优值。



重点监控：

- GPU 显存。
- 系统物理内存。
- Windows Commit。
- CPU 占用。
- 首 Token 延迟。
- 总推理速度。
- 请求成功率。

32GB 物理内存必须设置安全余量。



禁止以系统卡死、持续分页或 OOM 为代价追求吞吐量。

## 五、输出质量优化

针对 TP-PHASE-05 中源码理解 56/70 的问题：

1. 检查参数答案格式。
2. 明确输出协议。
3. 增加 Schema 校验。
4. 对格式错误实施有限次数的重新生成。
5. 保存原始响应和修复后响应。
6. 增加对应回归测试。

针对反馈机制：

1. 分析 4 次反馈中 3 次未进入有效补测的原因。
2. 优化反馈候选筛选。
3. 增加原版测试校验。
4. 保证有效候选才能进入变异测试。
5. 记录反馈转化率和新增杀死变异数量。

不得通过修改变异分母、删除困难样本或降低验收标准提高成绩。

## 六、测试与验收

必须执行：



A. 模型统一性

- 全部模块调用实际模型身份检查。
- 搜索并消除正式链路中的旧模型硬编码。
- 确认所有正式 AI 请求均经过统一 Provider。

B. 功能回归

- F01 → F02 → F03 → F04 → F13。
- 测试正常响应、空响应、超时、异常 JSON。
- 测试 Ollama 中断与恢复。
- 测试并发请求和队列调度。

C. 质量回归

- 沿用 PHASE-05 的 10 个项目和 117 个预登记变异位置。
- 保持相同评测协议。
- 保留模板、初始 27B 和反馈后 27B 的历史对照。
- 单独记录新版本表现，不能覆盖历史结果。

D. 稳定性

- 连续 100 次请求。
- 长时间连续运行。
- 4K、8K、16K 上下文压力测试。
- 记录峰值物理内存、Commit、显存及吞吐量。
- 任何可能导致系统失去响应的测试必须提前设置保护。

## 七、工程纪律

1. 先审计，再修改。
2. 保留 PHASE-05 实验分支和原始证据。
3. 不覆盖历史验收报告。
4. 每项修改有独立测试。
5. 每个阶段形成可追溯提交。
6. 不允许通过模拟数据冒充真实推理。
7. 不允许将配置成功等同于推理成功。
8. 不允许为了通过测试修改真实业务判定逻辑。

## 八、最终交付

交付：

- 模型统一架构。
- 统一 Provider 源码。
- 模块迁移清单。
- 旧模型调用审计报告。
- 性能和内存报告。
- 端到端测试报告。
- 变异测试对照报告。
- Git 提交记录。
- 最终生产启用状态。

最终状态必须明确区分：



READY_FOR_PRODUCTION\
READY_WITH_LIMITATIONS\
BLOCKED



只有真实推理、全链路回归和资源稳定性全部通过，才允许标记 READY_FOR_PRODUCTION。
