# TP-PHASE-01 补充要求：PyCharm 原生 Run 一键启动

这是 TestPilot AI 的强制工程要求，优先级为 P0。

## 1. 核心要求

项目必须支持在 Windows 11 环境下通过 PyCharm 直接运行。



用户操作流程必须是：

1. 使用 PyCharm 打开 D:\TestPilot AI。
2. 配置项目 Python Interpreter。
3. 打开项目根目录 main.py。
4. 点击绿色 Run 按钮。
5. 自动启动完整应用。
6. 自动打开默认浏览器。
7. 访问 http\://127.0.0.1:8000。

不要求用户手动执行 uvicorn、npm、npm run dev 或其他终端启动命令。

## 2. 架构调整

正式采用 Python 主导的单服务架构：

- FastAPI：后端和路由
- Jinja2：页面模板
- HTML/CSS/JavaScript：前端交互
- Python AST：代码分析
- Pytest：测试执行
- Hypothesis：属性测试
- SQLite：数据存储

不再强制依赖 React、Vite、Node.js 和 npm。



使用模块化设计，确保每个业务模块都能在 PyCharm 中独立打开和修改。

## 3. 入口文件

必须在项目根目录创建 main.py。



要求：

- 支持直接运行。
- 正确导入 FastAPI 应用。
- 启动 Uvicorn。
- 使用127.0.0.1作为默认监听地址。
- 自动打开浏览器。
- 端口冲突时提供清晰错误信息。
- 启动失败时给出可读日志。
- 正常退出时清理应用资源。
- 不启动重复服务。
- 不使用不必要的管理员权限。

生产演示模式与开发调试模式需要明确区分。

## 4. PyCharm 配置

提供：

- requirements.txt
- .run/TestPilot_AI.run.xml
- README.md 中的 PyCharm 启动教程
- Python Interpreter 配置说明

确保用户打开 main.py 后即可使用 Run 按钮。

## 5. 模块化开发

禁止将所有代码写在 main.py。



main.py 只负责：

- 初始化应用
- 配置启动参数
- 启动服务
- 浏览器打开

业务逻辑必须分别放在 backend、frontend、tests 等目录。



每个核心模块应当能独立调试和测试。

## 6. 启动验收

必须完成以下测试：

1. PyCharm Run 启动成功。
2. 浏览器自动打开。
3. Dashboard 正常显示。
4. 前端与后端接口通信正常。
5. SQLite 正常连接。
6. 测试执行模块可调用。
7. 停止服务后能够重新启动。
8. 端口占用时能够正确提示。
9. 通过 PyCharm Debug 模式可以设置断点。
10. 不依赖独立前端服务即可使用核心功能。

创建：

不得仅凭代码静态检查宣称通过。
