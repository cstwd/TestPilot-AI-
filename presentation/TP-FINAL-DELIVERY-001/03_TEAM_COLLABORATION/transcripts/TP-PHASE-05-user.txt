## 2. T01：模型环境审计与加载

检查：

- Qwen3.8-27B 文件是否下载完整。
- 实际模型格式。
- 量化类型 UD-IQ3_XXS。
- 模型架构及 Tokenizer。
- SHA256。
- 推理后端兼容性。
- RTX 5080 Laptop 显存。
- 系统可用内存。

确认兼容后启动真实模型。



如果现有推理后端不兼容，先分析原因，再选择合适的本地推理方案。



禁止在未经确认的情况下重新下载模型。



记录：

- 模型加载时间。
- 首 Token 延迟。
- 平均输出速度。
- GPU 峰值显存。
- 系统峰值内存。
- 10 次连续推理稳定性。

## 3. T02：源码理解能力

准备 10 个不同复杂度的真实 Python 测试项目。



评估：

- 函数识别。
- 参数理解。
- 返回值分析。
- 条件分支识别。
- 边界条件推理。
- 异常路径识别。
- 潜在缺陷定位。

每项使用标准化评分规则，保留模型原始输出。

## 4. T03：AI 测试生成

接入现有 F09，不重建测试生成模块。



要求：

- 真实 Qwen3.8 推理。
- 生成真实 Pytest 文件。
- 通过 Python AST 检查。
- 检查测试函数和断言。
- 在原版源码上运行。
- 拒绝不符合原始程序行为的错误测试。
- 保存生成过程和模型响应。

## 5. T04：Mutation Testing 对照

使用 F13 建立四组对照：



A：原有 qwen2.5-coder:0.5b 本地模型。



B：模板生成。



C：Qwen3.8 初始测试。



D：Qwen3.8 Mutation Feedback 优化后测试。



统一：

- 源码。
- 变异清单。
- 测试执行环境。
- 变异状态分类。
- 评分分母。

保留 PHASE-04 的 bonus.py 和原始九项变异，作为历史基准。



新增多文件、不同复杂度的 Python 项目，扩大测试规模。



每组至少进行三次独立生成，记录随机性和稳定性。



不能只选择有利于 Qwen3.8 的项目。

## 6. T05：Mutation Feedback

将存活变异、源码差异和执行证据交给 Qwen3.8。



要求：

- 分析未覆盖行为。
- 生成补充测试策略。
- 生成测试代码。
- 在原版源码校验预期。
- 拒绝错误断言。
- 对全部原始变异重新执行。
- 比较优化前后的 Mutation Score。

严禁修改用户原始源码。

## 7. 评估指标

必须记录：

- 初始 Mutation Score。
- 最终 Mutation Score。
- AI 候选原版校验通过率。
- 测试执行成功率。
- 变异检出率。
- 测试生成耗时。
- 模型推理速度。
- 显存峰值。
- 系统内存峰值。
- 多轮生成稳定性。

将模型能力、测试质量和推理性能分别评分。

## 8. 阶段目标

研究目标：

- Qwen3.8 初始测试质量超过现有模板基线。
- Mutation Feedback 能进一步提高测试质量。
- 候选断言具备较高的原版校验通过率。
- 连续任务稳定运行。
- API 费用为零。

参考目标：

- 初始 Mutation Score ≥55%。
- 优化后 Mutation Score ≥70%。
- 候选原版校验通过率 ≥80%。

以上为目标，不允许为了达到目标修改评分规则。
