# WP09-001 六页业务闭环验收

Codex 通过 Microsoft Edge 使用 `main.py` 启动的同源服务，以独立 SQLite 数据目录验收。两个版本均从 F01 浏览器导入。F03 使用页面现有的 `template` 模式，测试和回归由现有 WASI Pytest 执行器完成。生成成功、静态检查通过、首次 Pytest 失败分别验收。

## 验收记录

| 阶段 | Edge 操作与持久化结果 |
| --- | --- |
| F01 项目与版本 | 新建项目 `#2`，导入 `telemetry.py` v1 `#1` 和 v2 `#2`，逐次核对源文本、独立文件 ID、修订号和 SHA-256 |
| F02 AST 分析 | 从 F01 打开 v2，再切到 v1。图谱数量与真实 AST 符号和包含关系一致。两版 `magnitude` 的定义均位于第 6 行，从节点切换到 Source 核对定义 |
| F03 套件与首跑 | 从 v1 所选符号进入 F03。套件 `#1` 归属文件 `#1`，静态检查通过。首次运行 `#1` 由两个负数示例触发真实断言失败 |
| F04 重新执行 | 用套件 `#1` 执行 v1，持久化运行 `#2`。三个通过、两个失败。选择 `test_generated.py::test_example_2`，日志全文与持久化文本一致 |
| F05 缺陷及回归 | 从 `#2` 的失败用例登记缺陷 `#1`。Diff 指出 `return value` 与 `return abs(value)` 的差异，候选版本为 v2。确认回归后，原套件在 v2 上生成运行 `#3`。缺陷按服务端记录为已解决，原始失败证据保持可读 |
| F06 指标与导出 | 选择运行 `#3`。通过 5、失败 0、错误 0、跳过 0，通过率 100%（5/5），行覆盖率 71.43%（5/7）。报告可追溯至套件来源 v1、被测 v2、缺陷 `#1` 与回归 `#3` |

本系统使用文件记录的不可变 `id` 表示版本身份。`revision` 列分别为 1、2。项目、文件、符号、套件、运行、缺陷和报告摘要均由实测记录提取。 [身份清单](raw/workflow-identities.json) · [原始报告快照](raw/report-snapshot.json)

## 切换与报告快照

- F02 选定符号进入 F03 后，浏览器后退恢复符号，前进恢复目标函数。F04 直达链接携带真实 v1、套件和首跑 ID。
- F05 保留原始运行 `#2`、`nodeid` 和套件 `#1`。公共链接采用候选 v2，原始证据链接继续采用 v1，回归入口用 v2 与回归运行 `#3` 返回 F04。历史运行 `#1`、`#2`、`#3` 均可读取。
- F06 刷新后保持 `run=3`。F06 可打开 F04 原运行与 F05 对应缺陷，后退回到同一报告。切换到独立空项目时，页面清除旧报告与运行参数。
- 报告 API、既有 `/export` API、页面下载的 JSON 逐对象核对一致。单独 Edge 上下文以 `file://` 打开下载的 HTML，逐段对照运行身份、项目、版本、计数、分母、文件及套件 SHA、缺陷与回归证据。HTML 的证据链接指向验收时本机服务，离线文件本身可直接阅读。F06 的既有打印/PDF 入口保留。
- 主线记录 7 次业务写请求，对应一次建项目、两次文件导入、一次生成、一次重跑、一次登记缺陷和一次修复回归。刷新、前进、后退和导出均未增加写请求。主线期间 API 无 HTTP 错误，浏览器无控制台异常。另一个导航定向测试注入 503 验证文件清单报错时仍保留已知项目。
