# TP-PHASE-04：Mutation Testing Engine 开发任务

项目：TestPilot AI



模块：F13 Mutation Testing Engine

## 1. 目标

在现有 F07-F12 AI 测试引擎基础上，增加完整的 Python Mutation Testing 能力。



核心目标：



通过自动生成代码变异，评估 AI 生成的测试是否能够发现真实代码行为变化，并将存活变异反馈给 AI，自动补充测试用例。



坚持零 API 费用和本地模型推理路线。

## 2. 开发前审计

检查：

- F07-F12 当前接口。
- Pytest 执行环境。
- Sandbox 安全机制。
- Coverage.py 集成。
- 本地 AI Provider。
- 当前测试报告数据结构。

不得破坏此前三个阶段的验收记录。

## 3. 工具评估

分别评估：

- mutmut
- Cosmic Ray

通过独立基准项目比较：

- 安装兼容性。
- 变异算子覆盖范围。
- Pytest 集成能力。
- 执行性能。
- 并行执行能力。
- 报告可解析性。
- Windows 11 兼容性。
- 隔离环境兼容性。

根据实际结果选择生产工具，不要仅凭文档判断。

## 4. F13 功能要求

F13-01：Mutation Generator

- 自动生成代码变异。
- 支持条件、比较、算术、逻辑和返回值变异。
- 保留原始源码。
- 每个变异生成唯一 ID。

F13-02：Mutation Executor

- 隔离执行变异版本。
- 调用现有 Pytest 执行器。
- 捕获通过、失败、错误和超时。
- 支持执行终止和资源限制。

F13-03：Mutation Analyzer

- 识别 Killed Mutants。
- 识别 Survived Mutants。
- 识别等价变异候选。
- 区分超时和执行错误。
- 输出结构化报告。

F13-04：Mutation Score

- 正确计算变异得分。
- 保留完整统计分母。
- 单独记录等价变异。
- 不允许通过过滤困难变异人为提高得分。

F13-05：AI Mutation Feedback

- 将存活变异对应的源码位置交给 AI。
- 分析当前测试为何未发现行为变化。
- 生成有针对性的补充测试。
- 重新执行 Pytest。
- 重新运行相关变异。
- 保存优化前后对照结果。

## 5. 重点验收场景

至少覆盖：

1. 比较运算符变异。
2. 算术运算符变异。
3. 条件分支变异。
4. 布尔逻辑变异。
5. 返回值变异。
6. 异常处理变异。

必须使用真实源码、真实变异和真实测试执行。

## 6. 关键保护

- 不允许直接修改用户原始源码。
- 所有变异均在独立副本中执行。
- 不允许把模型自行声称发现的变异当作实际变异。
- 不允许把测试执行错误计为 Killed。
- 不允许把超时直接算作成功杀死。
- 不允许将等价变异随意计入分母调整。
- 所有运行记录可追溯。
