同时将 F02 已验证的视觉语言整理为可供 F01–F06 复用的公共 Design System。



视觉要求：

- GitNexus-inspired dark developer workspace。
- 深色石墨背景。
- 紫色作为主要品牌强调色。
- 蓝色、青色作为辅助强调色。
- 文件树、版本列表、代码 Inspector 采用统一面板语言。
- 细边框、克制阴影、清晰的层次关系。
- Inter / 本地中文字体回退。
- JetBrains Mono / Consolas 代码字体回退。
- 统一 Lucide 风格图标。

禁止将 F01 做成传统白底企业管理后台。

## 二、实施前审计

1. 检查当前 Git HEAD 和工作区状态。
2. 检查 F02 最终实现提交及公共样式。
3. 检查 F01 当前模板和 JavaScript。
4. 检查项目创建、文件导入、版本查询和源码预览 API。
5. 检查原有 F01 自动化测试。
6. 检查并行开发任务及未提交文件。
7. 确认当前项目数据模型与文件版本身份。

不得假设 F02 的全部样式已经提取为公共组件，应先识别并整理。

## 三、公共 Design System 提取

从 F02 提取：

- 背景与面板 Token。
- 文本层级。
- 紫蓝强调色。
- 状态色。
- 边框和圆角。
- 间距体系。
- 按钮和输入框。
- 标签和状态徽标。
- 搜索框。
- 文件树。
- 代码查看器。
- Inspector。
- Loading、Empty、Error 状态。

统一放入公共 CSS 和适当的 Jinja 组件。



不要简单复制 F02 的整份页面 CSS。



不得破坏 F02 已验收的图谱样式、动画和交互。

### 中央文件与版本管理

实现：

- 当前项目文件清单。
- 文件名搜索。
- 同名文件的版本分组。
- 最新版本标识。
- 历史版本展开。
- 版本选择。

- 文件摘要和版本信息。

### 右侧 Inspector

实现：

- 文件名称。
- 项目名称。
- 文件 ID。
- 不可变版本 ID。
- 修订版本号。

1. 使用真实 project_id。
2. 使用真实 file_id。
3. 保留不可变版本身份。
4. 跳转现有 F02 路由。
5. 确保 F02 加载的是所选版本。
