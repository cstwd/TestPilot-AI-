## 三、页面设计规范

建立 Visual Intelligence Studio。

### A. 顶部工具栏

包含：

- TestPilot AI 品牌标识。
- 当前项目。
- 当前文件。
- 文件版本。
- 图谱搜索。
- 节点数量。
- 关系数量。
- 设置与帮助入口。

必须始终明确当前分析对应的项目和不可变文件版本。

### B. 左侧 Explorer

建议宽度 220–250px。



包含：

- 项目文件列表。
- 文件搜索。
- 文件版本选择。
- AST 符号树。
- 类和函数筛选。
- 节点类型图例。

点击符号必须定位到图谱对应节点。

### C. 中央 Graph Canvas

中央画布占据主要空间。



必须实现：

- 节点渲染。
- 结构关系连线。
- 节点渐进式出现。
- 连线逐步绘制。
- 节点选择高亮。
- 邻接结构聚焦。
- 图谱缩放。
- 画布平移。
- Fit to Screen。
- Reset View。
- 图谱搜索与定位。
- 节点过滤。
- 暂停与继续动画。
- 已保存分析结果重新播放。

节点类型建议：

- File：蓝色。
- Class：紫色。
- Function：青色。
- Method：黄绿色。

必须根据实际 AST 数据决定节点种类和数量。



不允许凭空创建不存在的函数、类、方法或关系。

### D. 右侧 Inspector

建议宽度 320–380px，可折叠。



包含三个标签：

1. Overview
2. Source
3. Structure

Overview：

- 节点名称。
- 节点类型。
- 函数签名。
- 参数。
- 返回注解。
- 文档字符串。
- 源码起止行。
- 父级信息。

- 只读代码。
- 语法高亮。

- 自动滚动定位。

Structure：

- 真实父子结构。
- 当前节点的父节点。
- 当前节点的子节点。
- 可以返回父节点或展开子节点。

缺少数据时显示明确的空状态。

### E. 底部 Analysis Console

展示：

- 当前请求状态。
- 当前文件版本。
- 分析结果数量。
- 文件数量。
- 类数量。
- 函数数量。
- 真实关系数量。
- 实际分析耗时（可测量时）。
- 分析错误和警告。
- 动画播放状态。

禁止将模拟进度显示为真实后端进度。

## 四、动画设计

采用 Cinematic 动态呈现。



阶段一：SCANNING

- 显示真实文件分析请求状态。
- 获取真实分析结果。
- 节点按顺序逐步出现。

阶段二：PARSING

- 按真实层级显示文件、类、函数和方法。
- 不创建虚构节点。
- 逐步展开结构。

阶段三：STRUCTURE BUILDING

- 真实父子关系逐条绘制。
- 节点逐步连接。
- 保持整体图谱布局稳定。

阶段四：INSPECTION

- 当前节点高亮。
- 邻接节点适度突出。
- Inspector 同步更新。
- Source 自动定位。

阶段五：COMPLETE

- 图谱完成布局。
- 显示真实分析统计。
- 可以重新播放可视化动画。
- 可以继续探索和查看源码。

建议动画参数：

- 节点出现：250–400ms。
- 连线绘制：350–650ms。
- 选中转场：180–250ms。
- 完成收束：500ms。

动画采用分批播放，避免大量节点同时执行昂贵的动画。



注意：



当前分析 API 是否提供真实阶段进度，必须审计确认。



如果当前 API 一次性返回完整分析结果：

- 请求等待期间使用真实等待状态或不确定进度提示。
- 收到结果后执行图谱渐进式展示。
- 不得伪造实时解析百分比。

暂停、继续和重新播放只控制前端动画，不影响已保存分析结果。

## 五、数据模型与关系约束

必须设计统一 Graph Data Adapter。



建议规范：



GraphNode：

- id
- type
- name
- qualified_name
- file_id
- version_id
- start_line
- end_line
- signature
- parent_id

GraphEdge：

- id
- source
- target
- relation_type

以上字段按现有 API 实际数据映射，不存在的字段不得伪造。



第一版支持有证据的结构关系：

- File contains Class。
- File contains top-level Function。
- Class contains Method。
- Nested definition contains child definition（仅当解析结果提供对应层级）。

禁止把包含关系描述为调用关系。



禁止凭空生成调用次数、执行耗时、复杂度评分和测试关联。



未来可以扩展真实调用关系、测试覆盖关联和缺陷关系，但必须有独立的数据来源与接口契约。

## 六、交互要求

1. 点击节点更新 Inspector。
2. 点击文件定位对应文件节点。
3. 点击符号定位对应节点。
4. 点击源码定位高亮对应代码行。
5. 点击源码行可以反向定位符号（仅对有明确范围的定义生效）。
6. 搜索符号可以聚焦图谱。
7. 过滤节点后保留可恢复的完整数据。
8. 空白处点击清除选择。
9. 双击节点聚焦其局部结构。
10. 缩放、平移、复位和适配全部正常工作。
11. 图谱动画可以暂停、继续、重新播放。
12. 分析完成后可以重新读取同一结果。
13. 切换文件版本时清除旧版本选择，重新加载对应分析。
14. 刷新页面后通过现有稳定 ID 和路由参数恢复可恢复的分析上下文。
